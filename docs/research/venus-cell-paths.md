Research for hub issue #84 (child of map #83, "Per-cell BMS data on battery").

## Key finding up front

Victron's own documented battery path list has **no per-cell voltage, per-cell balancing, per-probe temperature, MOSFET temperature, cell diff, ChargeMode, or Allow-to-balance path**. Victron documents only min/max cell voltage and temperature (and their cell IDs) for "Lynx Smart BMS & Lynx Ion only" (`VW` Battery section). Everything per-cell, per-probe or limit-reason is a **dbus-serialbattery extension** under the same `com.victronenergy.battery` service type. A vendor-neutral `battery` entity must therefore treat per-cell arrays, probe temperatures and MOSFET temperature as optional, driver-specific data.

## How paths appear on MQTT

- Topic: `N/<portal ID>/<service_type>/<device instance>/<D-Bus path>`; service type is the part of the D-Bus service name that describes the service (`com.victronenergy.battery.*` becomes `battery`), the instance is the `/DeviceInstance` number (dbus-flashmq README, "Topic structure").
- Payload: the value wrapped in a dict as JSON, `{"value": 936}`.
- Invalid value: on D-Bus an invalid value is an empty `ai` array; on MQTT it is `{"value": null}` (`dbus-api.md` "An invalid value is represented by an empty array of integers ... On MQTT, an invalid value is represented by `null`"; dbus-flashmq README "Null for invalid values").
- Fixture confirms the shape: `N/PORTAL/battery/290/Dc/0/Temperature {'value': None}`, `N/PORTAL/battery/290/Dc/0/Current {'value': -7.8000...}`.
- Path segments are mirrored 1:1: D-Bus `/Voltages/Cell1` is `N/<portal>/battery/<instance>/Voltages/Cell1`; `/Cell/1/Volts` is `.../battery/<instance>/Cell/1/Volts`; `/Io/AllowToCharge` is `.../battery/<instance>/Io/AllowToCharge`.
- Units are SI except energy in kWh and temperature in degrees C (`dbus-api.md` conventions: "Use SI units ... Exceptions: use kWh for energy and degrees Celsius for temperature"). D-Bus carries no unit metadata, so the units below come from the docs / source, not the payload. (`gettextcallback` in dbus-serialbattery only affects the text shown in the GUI/`GetText`, not the MQTT value.)
- Keepalive: dbus-flashmq only publishes after a read request to `R/<portal ID>/keepalive` (60 s timeout). Out of scope for path mapping, noted for completeness.
- Multi-battery caveat: each BMS is its own `battery` service with its own `<instance>`; the instance for dbus-serialbattery is the `/DeviceInstance` it registers (`DH#L603`).

## 1. Per-cell voltages, cell max/min/diff

Layout is selected by `BATTERY_CELL_DATA_FORMAT` in `config.default.ini#L559-L564` (default `1`): `0` = no per-cell paths, `1` = `/Voltages/CellN` (+ balances), `2` = `/Cell/N/Volts`, `3` = both. Per-cell paths are created at startup for `len(battery.cells)` cells (`DH#L829-L852`), so the set of paths depends on the cell count the BMS reports.

| Path                                                   | Unit                                                                                     | Sign          | Null behaviour                                                                                                                                                          | Optional?                                                                                | Source                                                                           |

Notes:

- The reference screenshot's "Cell max" and "Cell min" are `/System/MaxCellVoltage` and `/System/MinCellVoltage` (`QML` binds those two; "Cell max"/"Cell min" labels at QML lines ~422 and ~445). The "Cell Voltages" sub-page binds `/Voltages/Cell<N>`, `/Voltages/Sum`, `/Voltages/Diff` (`qml/gui-v2/3.8x/PageBatteryDbusSerialbatteryCellVoltages.qml#L66,L100,L104`). The GUI only reads the format-1 layout; format 2 is for other consumers.
- Cell index is 1-based and contiguous. Cell count is dynamic per BMS and can change at startup; a consumer should discover the array by subscribing to `.../Voltages/#` rather than assuming a fixed count.
- Because D-Bus invalid is not distinguishable from absent on a per-path basis in MQTT retained state, "cell does not exist" (path never published) and "cell exists but invalid" (`null`) are different situations.

## 2. Temperatures (per probe, MOSFET, aggregate)

dbus-serialbattery supports a MOSFET sensor plus four numbered probes. Temperatures are clamped to -20..100 degC in `to_temperature()` (`BAT#L555-L569`), so a missing sensor reading is `None` (never a sentinel), and an extreme reading is clipped rather than invalid.

| Path                                                            | Unit                                                                         | Sign                          | Null behaviour                                                                                                                                                                     | Optional?                                                                                      | Source                                                                   |
| --------------------------------------------------------------- | ---------------------------------------------------------------------------- | ----------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------ |
| `/System/MOSTemperature`                                        | degC (1 dp)                                                                  | signed, clamped to [-20, 100] | `None` if the BMS has no MOSFET probe / not read                                                                                                                                   | Driver-specific (dbus-serialbattery; not in Victron docs)                                      | `DH#L752`, `DH#L1226`, `BAT#L564-L565`; QML "MOSFET" row (`QML#L154`)    |
| `/System/Temperature1` ... `/System/Temperature4`               | degC (1 dp)                                                                  | signed, clamped               | `None` when the BMS has fewer probes                                                                                                                                               | Driver-specific                                                                                | `DH#L753-L760`, `DH#L1227-L1234`                                         |
| `/System/Temperature1Name` ... `/System/Temperature4Name`       | string label                                                                 | n/a                           | Config value (`TEMPERATURE_n_NAME`, defaults `Temp 1`..`Temp 4`); a string, never `None` once published                                                                            | Driver-specific                                                                                | `config.default.ini#L578-L587`, `DH#L1228,L1230,L1232,L1234`             |
| `/Dc/0/Temperature`                                             | degC (1 dp)                                                                  | signed                        | Mean of probes listed in `TEMPERATURE_SOURCE_BATTERY` (default `1,2,3,4`) that are non-`None`; `None` when none are valid. **MOSFET is not included** (map holds sensors 1-4 only) | Victron-documented (`VW` "/Dc/0/Temperature <- °C Battery temperature")                        | `DH#L733`, `DH#L1143`, `BAT#L2008-L2028`, `config.default.ini#L573-L575` |

| `/System/MinTemperatureCellId` / `/System/MaxTemperatureCellId` | string (the probe's configured name, e.g. `Temp 2`, via `TEMPERATURE_NAMES`) | n/a                           | `None` when no valid probe                                                                                                                                                         | Victron-documented for Lynx (as cell ID); the value semantics differ (probe name, not cell id) | `VW`; `DH#L749,L751`, `BAT#L2040-L2070`                                  |

Notes:

- The screenshot's "Temperatures (Battery, MOSFET, Temp 1-4)" map to `/Dc/0/Temperature`, `/System/MOSTemperature`, `/System/Temperature1..4` (+ `...Name` for the row labels) (`QML#L148-L197`).
- Per-probe temperature is not a per-cell temperature: Victron's "cell temperature" naming (`MinCellTemperature`) is repurposed by dbus-serialbattery for probes.
- Names are user configuration; do not hard-code "Temp 1".

## Optional or driver-specific summary

- **Victron-guaranteed for any `battery` service** (varies by product): `/Dc/0/Voltage`, `/Dc/0/Current`, `/Dc/0/Power`, `/Soc`; alarms as listed per product.
- **Victron-documented but only for BMS-class devices** (Lynx Smart BMS / Lynx Ion, and what dbus-serialbattery imitates): `/System/{Min,Max}CellVoltage`, `/System/{Min,Max}VoltageCellId`, `/System/{Min,Max}CellTemperature`, `/System/{Min,Max}TemperatureCellId`, `/System/NrOfCellsPerBattery`, `/Balancing`, `/Io/AllowToCharge`, `/Io/AllowToDischarge`, `/State`, `/ErrorCode`.
- **DVCC paths**: `/Info/MaxChargeVoltage`, `/Info/MaxChargeCurrent`, `/Info/MaxDischargeCurrent` for batteries that control the charger; absent on a plain SmartShunt (the fixture has none).
- **dbus-serialbattery only (no Victron doc)**: `/Voltages/CellN`, `/Cell/N/Volts`, `/Voltages/Sum|Diff` (or `/Cell/...`), `/Balances/CellN`, `/Io/AllowToBalance`, `/Io/AllowToHeat`, `/System/MOSTemperature`, `/System/Temperature1..4`, `/System/Temperature1..4Name`, `/Info/ChargeMode`, `/Info/ChargeLimitation`, `/Info/DischargeLimitation`, `/Info/MaxChargeCellVoltage`, `/Dc/0/MidVoltage` reuse, `/CurrentAvg`, `/Soh`, `/Heating`, `/Info/Heating*`, `/Alarms/StateOfHealth`, `/JsonData`.
- **Config-dependent** within dbus-serialbattery: which cell layout exists (`BATTERY_CELL_DATA_FORMAT`), whether `/SocBms`, `/CapacityBms`, `/ConsumedAmphoursBms` exist (`SOC_CALCULATION`), and the `TimeToSoC/*` paths (`TIME_TO_GO_ENABLE`).
- **Per-BMS**: the number of cells, number of probes, whether MOSFET temperature, balance state or alarms are populated all depend on the specific BMS driver in `bms/`. A path that is registered but not populated is `null`.
- **Other services that expose cells** (not read): Victron's own Lynx Smart BMS / Lynx Ion publish only min/max/IDs, not an array, per `VW`. No other Victron-documented service publishes per-cell voltages.

## Mapping implications (for the hub `battery` entity)

These follow from the findings; they are not decisions.

- Arrays for cells (voltage, balancing) cannot come from Victron-documented paths alone; they depend on the dbus-serialbattery layout. Probe temperatures and MOSFET temperature likewise.
- Distinguish "path never seen" from "path seen with `null`"; and note `Io/AllowToCharge|Discharge` never go `null` (unknown reads as `0`), `Balances/CellN` never go `null` for existing cells (unknown reads as `0`), and `Info/Max{Charge,Discharge}Current` never revert to `null`.
- Sign: only current/power carry sign (+ charge, - discharge). Everything else in this note is non-negative except temperatures.
- Limit "reason" strings are free text built from a small fixed vocabulary; they are display aids, not an enum.
